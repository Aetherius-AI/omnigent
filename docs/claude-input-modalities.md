# Claude native image input

Managed Claude catalogs can advertise input capabilities through the string
`env.OMNIGENT_CLAUDE_MODEL_INPUT_MODALITIES` in managed settings. Its value is a
JSON object mapping exact model IDs to arrays containing `text`, `image`, or
both. For example:

```json
{"provider.text-model":["text"],"provider.vision-model":["text","image"]}
```

This optional Omnigent contract is independent of Claude's `modelPicker`
schema. Omnigent enriches only models returned by the actual CLI catalog, and
only when Claude uses the ambient managed provider. Explicit provider
configuration does not inherit another provider's capabilities. Unknown,
malformed, or conflicting metadata leaves existing delivery behavior intact.
The JSON is limited to 64 KiB, 256 entries, and 256 characters per model ID.

Before forwarding a fresh web image to a known text-only model, the server
returns an actionable validation error and retains the complete message and
its error banner. Uploaded `input_image` references are recognized directly;
an `input_file` reference uses session-scoped file metadata to recognize an
image without fetching its bytes. The user must choose a compatible model
and resend. Omnigent does not change the model or remove the image.

A refused message is stored with `delivery_status: "undelivered"`, which is
omitted from ordinary message rows. It remains visible after reload, and
Claude's cold-resume reconstruction excludes only that marked message. An
accepted message or steering input sharing the same response ID is retained.
The client's send ID remains available for an explicit resend; the existing
native transcript source ID still takes precedence for a mirrored item.

The executor repeats the guard immediately before terminal injection. Moving
from a known text-only model to a known image-capable model requires the live
terminal to confirm adoption before the image is injected. A refusal at this
later boundary preserves the session and the input, and remains an ordinary
reported executor failure. Server validation prevents the known incompatible
request from starting a turn; it does not hide failures from accepted turns.

This preflight covers fresh Omnigent web/API inputs. Direct terminal prompts,
existing imported image history, and images generated by tools still follow
the native CLI's behavior.

To verify manually on a host with the metadata installed, start a Claude
session with a known text-only model. Attach, paste, or drop an image and send
it with text. Expect “Image was not sent,” the complete retained message after
reload, and a usable session. Choose a known compatible model and explicitly
resend; expect one delivery. Repeat while another turn is running and confirm
its accepted messages remain in history after a cold resume.
